## 2. 已确认的产品决策

1. 产品是正规的东莞本地上门按摩预约平台。
2. 首期只支持东莞市，暂不建设多城市和城市合伙人体系。
3. 用户端、技师端、管理端位于同一个微信小程序中，通过账号角色和权限进入不同工作台。
4. 小程序使用原生微信小程序技术，不使用 uni-app、Taro 或 H5 套壳。
5. 后端使用 Java 和 Spring Boot，采用模块化单体架构，不拆微服务。
6. 用户下单时自行选择技师；管理员可在异常情况下改派技师。
7. 管理员维护项目基础价，也可为指定技师设置单独价格。
8. 用户通过微信支付向平台付款，平台线下审核后人工结算技师，不接自动分账。
9. 首版管理端是小程序内的移动管理端，不建设 PC 管理后台。
10. 阶段 1 已由项目方确认并实施；后续每个阶段仍须先确认方案再编码。

## 3. 首版业务边界

### 包含

- 微信登录、手机号授权、三角色权限和角色切换
- 技师入驻申请、资料审核、项目绑定、排班和上下架
- 项目及分类管理、技师单独定价
- 用户查看项目和技师、选择技师、地址和时间后下单
- 微信支付接口及开发环境模拟支付
- 完整订单履约、取消、退款、评价、投诉和售后流程
- 技师接单、出发、到达、开始和完成服务
- 管理员移动端管理项目、技师、订单、退款、结算和基础运营内容
- 技师收入台账及平台人工结算记录
- 订阅消息、操作日志、隐私和合规基础能力

### 不包含

- PC 管理后台
- 多城市、加盟商或城市合伙人
- 会员充值、储值余额和次卡
- 拉新返现、分销和多级佣金
- 技师动态广场、用户私聊和社区内容
- 自动抢单大厅和复杂智能派单
- 微信自动分账、自动提现和银行卡代付
- 隐私号、平台通话录音和实时位置轨迹

## 4. 待确认的业务默认值

以下默认值用于让 PRD 和开发计划可以完整落地，编码前应由项目方逐项确认：

| 编号 | 默认方案 | 可调整点 |
| --- | --- | --- |
| D-01 | 用户提交订单后 15 分钟未支付，订单自动关闭并释放预约时段 | 支付时限 |
| D-02 | 技师收到已支付订单后 10 分钟内接单；超时转管理员处理，不自动换技师 | 接单时限和超时策略 |
| D-03 | 技师拒单后进入管理员处理，用户可以等待改派或申请全额退款 | 拒单策略 |
| D-04 | 服务开始前 2 小时以上取消可全额退款；2 小时内由管理员审核 | 取消退款规则 |
| D-05 | 技师完成服务后用户有 24 小时投诉期；无投诉后订单进入可结算 | 售后保护期 |
| D-06 | 平台每周人工结算一次，管理员录入结算单号和凭证 | 结算周期 |
| D-07 | 首版上门费由管理员在订单中确认的固定规则计算，不做实时打车计价 | 上门费规则 |
| D-08 | 管理员可改派，但改派后的项目价格不变；产生差价由管理员人工处理 | 改派差价规则 |
| D-09 | 一个预约时段内，同一技师只能有一个有效订单 | 排班容量 |
| D-10 | 用户可从“项目选技师”或“技师选项目”两条路径下单 | 下单入口 |
